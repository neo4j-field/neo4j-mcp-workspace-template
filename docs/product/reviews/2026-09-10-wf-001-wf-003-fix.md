# WF-001 and WF-003 fix evidence

Date: 2026-09-10

## Outcome

The documented Claude Desktop lexical workflow now has both a runtime-schema
CI contract and an opt-in live, headless DXT smoke test. The exact maintained
DXT command reached PDF ingestion and embedding successfully. Verification used
the canonical `Chunk.text_embedding` property, and a second embedding call
correctly reported zero work rather than causing a false retry.

## Root mismatches

- The original Desktop examples used lexical arguments that did not agree with
  `create_lexical_graph`; the maintained example now supplies `path` and
  `output_dir`, and runtime MCP schemas enforce all call-shaped lexical examples.
- Desktop verification previously counted `c.embedding`, while the lexical
  writer stores `c.text_embedding`.
- The DXT starts published `mcp-neo4j-proxy@0.2.1`, and that published proxy
  pins lexical `0.2.0`; the repository lexical source is `0.2.1`. Inspection of
  the cached `0.2.0` package confirms its inventory still exposes `pageCount`
  rather than LEX-001's `sourcePageCount` and `pageNodeCount`. This remains
  tracked by DESK-001. The live smoke therefore verifies the two page concepts
  directly from `Document.totalPages` and graph `Page` nodes, without pretending
  the published inventory response is version-aligned.
- The published lexical package writes a PyMuPDF `fitz` deprecation warning to
  stdout during worker startup. FastMCP logs an invalid JSON-RPC line but the
  request completes. Desktop packaging should eliminate this stdio framing
  noise when DESK-001 aligns the packages.

## Added coverage

- `tests/contracts/test_desktop_lexical_runtime_contract.py` starts the current
  lexical FastMCP server object, discovers its runtime schemas, and checks every
  call-shaped Desktop lexical example. CI installs the lexical package and runs
  this test with the full contract suite.
- `tests/integration/test_desktop_lexical_smoke_mcp.py` reads the exact DXT
  command and arguments from the manifest, initializes the stdio MCP proxy,
  discovers tools, validates the documented calls against the published runtime
  schemas, parses a unique one-page PDF, polls completion, embeds, verifies
  canonical storage and page semantics, retries embedding once, and cleans only
  its unique namespace.
- `tests/fixtures/desktop/wf001_wf003_smoke.pdf` is the deterministic one-page
  smoke fixture. It was rendered and visually checked before use.

## Manual release boundary

No Claude Desktop GUI, extension configuration discovery, installation, or
restart behavior was tested. The sole manual release check is: install the built
DXT, restart Claude Desktop, and confirm the workspace tools are visible.

## Improvement feedback

Generate the DXT manifest and proxy child-package pins from one version source,
then run the live smoke against the just-built packages before publication. This
would close the current gap where source contracts pass while the installed DXT
still resolves older child packages.
