# N1 / N4 implementation — 2026-11-24

Implemented in parallel on the existing stabilization worktree. Existing edits and
commits were preserved. No configured user database, credentials or generated MCP
configuration were changed.

## N1 — native Docling hierarchy

Upgraded Docling to 2.152.0 (core 2.108.0), enabled native hierarchy, and retained
semantic heading levels through section parentage. Reading-order tree depth is no
longer guessed as heading depth. Structured and by-section chunking include full
heading paths; structured visual chunks retain captions, and merged small sections
retain every contributing path. The explicit hierarchy correction tool remains.
No automatic hierarchy LLM call is needed.

The installed Docling source confirms parsed-page retention is unnecessary for
native style inference; it remains disabled. The actual database test exposed an
incidental APOC dependency in Page/Element writes. Native Cypher map assignment and
removal now provide the same result without requiring that plugin.

## N4 — bounded ontology interchange

Added `import_ontology_spec(content)` and
`export_ontology_spec(ontology_name, format="yaml")` (`json` also supported).
The existing Ontology DB and schema-generation path remain the extraction path.
Imports create new ontologies atomically and refuse existing globally unique names.

The unchanged normative [1.1.0 schema](https://neo4j.com/docs/ontology-graph-spec/1.1.0/schema.json)
is bundled for offline validation and was verified in a built wheel. Supported:
four extraction scalar types, one key/label per node, fixed relationship endpoints,
required properties, and the template's normalizer/alias/blocklist/composed-name
extension. Unsupported semantics fail before writes with field paths. Export
canonicalizes identifiers to database names. YAML aliases, unsupported custom
metadata and non-filename-safe ontology IDs are rejected. No registry service or
DDL deployment was introduced.

Review caught and fixed empty normalizer chains and ambiguous multiple composed-name
targets, with regressions. The database tests verify generated Pydantic normalization,
semantic YAML/JSON roundtrip, collision refusal and rollback after a write failure.
